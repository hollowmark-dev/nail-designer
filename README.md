# nail_designer

スマホでネイルの図案（10本ぶん）を作るアプリ。テンプレ化したパーツを爪の上に置くだけで、手書きより速く1セット作れるようにする。

- データは端末内（IndexedDB）にのみ保存。サーバーには一切送らない
- 共有するのは**アプリ本体**。URLを教えて相手にも使ってもらう（作ったデザインは各自の端末に残る）
- アプリストアには公開しない。GitHub Pages に置いて URL を配る
- ビルドツールなし。`docs/` をそのまま配信する

設計と、そこに至る判断の記録は下の「Phase 0: 書き出し互換性の検証」以降にまとめてある。

## ローカルで動かす

```bash
python -m http.server 8021 --directory nail_designer/docs
```

`http://localhost:8021` を開く。

スマホの実機で見るときは、同じ Wi-Fi につないで `http://<PCのIPアドレス>:8021/` を開く
（ファイアウォールで Python の受信を許可する必要がある場合がある）。

注意: `navigator.share` / `navigator.storage` / Service Worker は HTTPS か localhost でしか動かないため、
LAN越しの http では試せない。公開版で確認すること。

### できること

**作る**
- 10本ストリップから1本選んで、拡大キャンバスで編集する
- 爪の形4種（ラウンド／スクエア／アーモンド／バレリーナ）× 長さ3段を10本まとめて変更
- パーツ **68種**（ベース8／縁11／柄10／モチーフ39）とテンプレ16種
- パーツはタグで絞り込める（定番・ガーリー・韓国風・オフィス・季節・動物・花・フルーツ など）
- 文字を入れる（欧文2書体を同梱。日本語は端末の標準フォント）
- 指でなぞって手書きの線を引く（太さ3段・色はパレット連動）

**速くする**
- テンプレをタップで1本まるごと完成、そこから微調整
- 1本を10本すべてに流し込む／薬指以外に流し込む／地の色だけ全部に／上段を反転して下段へ
- パレット9色。色を差し替えると10本ぶん全パーツが連動。配色セット3種
- 1本指ドラッグで移動、角ハンドルで拡大＋回転（15°スナップ）、中心線への吸着
- 重なったパーツは同じ場所を再タップで下へ巡回して選び分ける

**広く使う**
- **集中モード**（右上の ⤢）… ストリップを1行のラベルだけにし、ツールも低くしてキャンバスを最大化する。爪の表示が **184×285 → 355×554**（面積で約3.7倍）
- **ズーム**（2本指ピンチ、または＋／−ボタン）… 最大5倍。2本指のまま動かすとパンできる。1本指はそのまま描画・移動なので、**拡大して大きく描けば細い線も引きやすい**（データは爪の座標系のままなので、描いた線は小さく載る）

**残す・配る**
- Undo / Redo、編集のたび自動保存（debounce 500ms）
- PNG書き出し（10本シート／1本だけ、背景白or透過、輪郭線あり/なし）。使っている書体だけを埋め込む
- バックアップの JSON 書き出し・読み込み
- PWA（manifest / Service Worker / ホーム画面追加 / 更新通知）
- 初回起動の注意書き（iOSのホーム画面追加、LINE等アプリ内ブラウザの制約、データは端末内だけ）

### 実装中に見つけて直したこと

1. **`store.js` の `tx()` が、レコードが見つからないとき `request.result`（undefined）ではなく IDBRequest オブジェクトそのものを返していた。** 呼び出し側では「見つかった」ように見えるため、存在しない id を開くと空のエディタが立ち上がり、それが新しい作品として保存されてしまう。`'result' in req` で判定するよう修正
2. **リボンが小さいサイズで「∞」に見えていた。** 丸いループをやめ、結び目から外へ開く三角に描き直した
3. **パレットに緑が無く、葉・クローバー・クリスマスツリーが灰色だった。** 緑を1色足し、あわせて `migrate` が古いデータのパレットを既定の長さまで埋めるようにした（今後色を足しても古いデータが灰色にならない）
4. **三日月の円弧が、弦より短い半径を指定していて図形が潰れていた**（SVG仕様で半径が自動拡大され、2つの半円が打ち消し合っていた）。曲線2本で描き直した

### 見た目が弱いまま残っているもの

- レモン … 卵型に見える

`navigator.share` と `navigator.storage` は**セキュアコンテキスト（HTTPS か localhost）でしか露出しない**。
Service Worker も同じ。LAN越しの `http://192.168.x.x` では試せないので、公開してから確認する。

- `navigator.share({files})` で書き出した画像を他アプリへ渡せるか
- Service Worker が登録され、`sw.js` の `VERSION` を上げて再デプロイすると「新しいバージョンがあります」が出るか
- Android Chrome で「ホーム画面に追加」の提案が出るか
- iPhone で、ホーム画面に追加したアプリとして開けるか
- `navigator.storage.persist()`（**iOS Safari は元々非対応**。通らない端末ではバックアップ書き出しが唯一の保険になる）

## Phase 0: 書き出し互換性の検証

`docs/spike-export.html` — SVG → PNG の書き出しで何が使えるかを実機で確かめる自己診断ページ。
UIを作る前にここで描画方式を確定させる。ページを開くと自動で10項目を走り、画素を検査して合否を出す。

### 結果（2環境とも全10項目パス）

- **Android Chrome 148** / devicePixelRatio 2（アプリ内ブラウザ、localhost）
- **iOS 18.7 Safari 26.6.1** / devicePixelRatio 3 / 402x714（実機、LAN経由の http）

| # | 項目 | Chrome | Safari |
|---|---|---|---|
| T0 | blob: / data: どちらで `<img>` に読ませられるか | 両方可 | 両方可 → **blob: を既定にする** |
| T1 | clipPath（爪の形での切り抜き） | OK | OK |
| T2 | linearGradient | 差 206 | 差 208 |
| T3 | pattern の高解像度書き出し | 3倍=5%（circle と同値） | 3倍=5% → **ぼやけない。pattern を使ってよい** |
| T4 | 同一パーツ2個の id 衝突 | **衝突を再現**（接頭辞なし: 差 3 = 同色） | 衝突しない（差 251） |
| T5 | @font-face の base64 埋め込み | 差分 3.78% | 差分 3.38% → **文字機能は成立する** |
| T6 | paint-order による文字の縁取り | 白画素 2379 vs 0 | 2375 vs 0 |
| T7 | width/height 属性の省略 | `97x150` | `100x155`（＝等倍。2倍書き出しにならない） |
| T8 | canvas 汚染と toBlob | 汚染なし・5.8KB | 汚染なし・5.1KB |
| T9 | 爪の形4種 × 長さ3段 | 12通りOK | 12通りOK |

T9 の先端幅（長さを変えても一定＝先端が潰れていない）:

| | ラウンド | スクエア | アーモンド | バレリーナ |
|---|---|---|---|---|
| Chrome | 30 | 95 | 16 | 44 |
| Safari | 31 | 95 | 15 | 44 |

**T4 は Safari では衝突しなかった。** id の解決順が Chrome と違う。ただし Chrome では確実に壊れるので接頭辞の規約は必須。

**T7 は環境で壊れ方が違う。** Chrome は 97x150、Safari は viewBox どおりの 100x155（＝2倍指定が無視されて等倍になる）。どちらにせよ属性は必ず付ける。

### ここから確定した実装ルール

1. **描画のたびに `id` へ接頭辞を付ける。** パーツ内の `radialGradient` / `pattern` / `clipPath` の `id` と、それを指す `url(#…)` を同時に置換する。T4 で実際に衝突したので必須。作例にはリボンが2個並ぶ爪がある
2. **パーツの色は `{c0}` プレースホルダを文字列置換で実色に落とす。** `var(--c0)` は SVG-as-image で効かない環境があるため使わない
3. **書き出す SVG には必ず `width` / `height` 属性を付ける**（T7）
4. **外部参照を一切使わない。** SVG-as-image は外部CSS・外部画像を読まない。フォントは base64 で埋め込む
5. **`foreignObject` は使わない**（Safari で canvas を汚染する）
6. **爪の形は関数生成**（根元の曲線＋直線の側壁＋先端）。固定パスを縦に伸ばすと先端が潰れる
7. **座標は幅を100とする整数、レイヤーは `anchor`（root / tip / center）を持つ。** 長さを変えてもフレンチは先端に貼りつき、モチーフは中央に残る（T9で確認）

### 未確認（HTTPS でしか試せないもの）

`navigator.share` と `navigator.storage` は**セキュアコンテキスト（HTTPS か localhost）でしか露出しない**。
LAN越しの `http://192.168.x.x` で開いた iPhone で「なし」と出たのはこのためで、iOS の制約ではない。
Service Worker も同じ理由で LAN 経由では試せない。GitHub Pages に載せた時点で以下を再確認する。

- `navigator.share({files})` で書き出した画像を他アプリへ渡せるか
- `navigator.storage.persist()` が通るか（**iOS Safari は元々 persist に非対応。ホーム画面追加とバックアップ書き出しが唯一の保険になる**）
- Service Worker の登録・更新通知
- T5 は Google Fonts から woff2 を取得して検証した。実アプリでは `js/fonts.js` に base64 で埋め込んであり、書き出しへの反映は確認済み（使っている書体だけを埋め込む）
